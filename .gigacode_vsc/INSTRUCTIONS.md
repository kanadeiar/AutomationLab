# description: Архитектурные инструкции для IEC 61131-3 ST (любая среда)

> Все примеры кода — справочные. Применяй только то, что нужно в твоем проекте.

## Организация проекта

### Общие правила
- Старайся использовать стандартные инструкции.
- Используй выходные контакты FB напрямую в выражениях
- Создавай промежуточные перемены только если они улучшают читаемость
- Названия локальных переменных делай с маленькой буковки
- Названия глобальных, входных и выходных переменных делай с большой буковки

### Структура папок
```st
Project/ 
├── Logic/ ← Алгоритмы
├── Support/ ← HW, HMI, вспомогательное
├── TechnologyObject/ ← FBs, POUs, технологический объект
├── PLC_PRG.st             ← Главный циклический вызов
└── GVL.st
```

### Соглашения именования
| Постфикс | Тип | Пример |
|---------|-----|--------|
| `_PRG` | Program | `PLC_PRG` |
| `Type` | Data type | `ConveyorType` |
| `_DB` | Data | `Conveyer_DB` |
| `_FB` | Function block | `Conveyer_FB` |
| `_FC` | Function | `Conveyer_FC` |
| `_DB` | Datablock | `Conveyer_DB` |
| `_HW` | Hardware abstraction | `Hardware_HW` |

| Префикс | Тип | Пример |

| `DO_` | Output Hardware Signal | `DO_Motor` |

## Правила GVL

- Константы указывать так → `VAR_GLOBAL CONSTANT`
- Состояние системы указывать так → `VAR_GLOBAL RETAIN`
- Входы/выходы → `VAR_GLOBAL` (без RETAIN)
- Адресация через `AT %I`/`AT %Q` в объявлении
- Логика работает с символическими именами, не с прямыми адресами

## Правила Function Block

### Порядок секций
1. `VAR_INPUT` — входы
2. `VAR_OUTPUT` — выходы
3. `VAR` — локальные переменные

### Правила FB
- **Вызывать каждый MAIN_CYCLE** — таймеры, счётчики, edge-детекторы
- **Не мутировать VAR_INPUT** — использовать локальную копию
- **Инициализировать VAR** — `State : INT := 0;`
- **Использовать RETAIN** для сохраняемых состояний
- **Объявлять экземпляры** — `Conveyor1 : FB_Conveyor;`
- **Выходные параметры FB записывай напрямую через `=>` в вызове блока, а не отдельным присваиванием**

## Стандартные FB — когда использовать

### Таймеры
| FB | Когда использовать |
|----|-------------------|
| `TON` | Задержка старта, debounce |
| `TOF` | Задержка стопа, emergency hold |
| `TP` | Импульс фиксации, trigger |
| `CTU` | Счётчик деталей, циклов |
| `CTD` | Обратный отсчёт |
| `CTUD` | Балансировка, level control |

### Edge детекторы
| FB | Когда использовать |
|----|-------------------|
| `R_TRIG` | Нажатие кнопки, начало события |
| `F_TRIG` | Отпускание кнопки, конец события |

## Архитектурные паттерны

### State Machine (машина состояний)
- Использовать `CASE State OF` для перехода между состояниями
- Состояние хранить в `VAR` с инициализацией
- Обрабатывать Reset и Run

### Главный блок программы
1. Чтение входов / Абстракция железа
2. Технологические блоки
3. Обработка ошибок
4. Запись на HMI
5. Запись выходов

## Обработка ошибок

### Паттерн FB_ErrorHandler
- Паттерн использовать в тех случаях, когда требуется обработка ошибок по заданию
- Код ошибки в `VAR_OUTPUT ErrorCode`
- Таймер для сброса ошибки (TOF)
- Флаг `ErrorActive` — активна ли ошибка сейчас

## Цикловое выполнение

### Правила цикла
- Все FB вызывать каждый MAIN_CYCLE
- Таймеры вызывать каждый MAIN_CYCLE
- Не использовать `WHILE TRUE` в MAIN_CYCLE
- Использовать `CASE State OF` для State Machine

### Антипаттерны
#### Не делать
Прямая адресация в логике (IF %IX0.0 THEN ...)
Нет RETAIN для сохраняемых данных
Вызов FB без экземпляра (FB_Conveyor(Start := TRUE);)
Мутация входных параметров (Speed := Speed * 0.5;)
Вызов таймера по условию (IF Start THEN Timer(...);)
Никаких WHILE TRUE для выполнения цикличного кода.

#### Делать
Символическая адресация в GVL
RETAIN для сохраняемых данных
Экземпляр FB (Conveyor : FB_Conveyor; Conveyor(Start := TRUE);)
Локальная копия для мутации (LocalSpeed := Speed * 0.5;)
Таймер вызывается каждый цикл (Timer(IN := Start, PT := T#5s);)
PROGRAM выполняется циклически автоматически контроллером.
