# AutomationLab

Лаборатория опытно-экспериментальных технологических приложений.

Учебный проект управления конвейером на ПЛК: программа на языке **ST (Structured Text)** по стандарту **МЭК 61131-3**.
Целевой контроллер — **Овен ПЛК210**.

## Задача проекта

Управление включением/отключением конвейера:
- НЗ датчик в начале — запуск ленты при обнаружении коробки
- НЗ датчик в конце — остановка ленты при обнаружении коробки
- Алгоритм: RS-триггер с самоподхватом

## Архитектура (Три слоя)

```
AutomationLab/
├── PLC_PRG.st              ← Точка входа, циклический вызов
├── GVL.st                  ← Глобальные переменные ввода/вывода
├── ConveyorObject/
│   ├── ConveyorMain.st     ← Чистый оркестратор
│   ├── HardwareInput.st    ← Чтение датчиков
│   ├── HardwareOutput.st   ← Запись на двигатель
│   ├── LogicDevice.st      ← Чистая логика RS-триггера
│   └── HMIInterface.st     ← Сопряжение с панелью оператора
└── README.md
```

### Назначение блоков

| Блок | Ответственность |
|------|----------------|
| `PLC_PRG` | Точка входа, циклический вызов |
| `ConveyorMain` | Чистый оркестратор: соединяет HardwareInput → LogicDevice → HardwareOutput → HMIInterface |
| `HardwareInput` | Чтение GVL-датчиков (DI_SensorA/B) → BoxOnStart/BoxOnEnd |
| `HardwareOutput` | Запись команды на двигатель в GVL (ComRotate → DO_ComMotor) |
| `LogicDevice` | RS-триггер: включить/выключить ленту по сигналам |
| `HMIInterface` | Управление лампочкой на панели оператора (BeltRun → DO_LampRun) |
| `GVL` | Глобальные переменные — привязка к физическим входам/выходам |


### Ключевые принципы

1. **Нет STRUCT-посредников** — данные передаются через BOOL на входах/выходах FB
2. **ConveyorMain — оркестратор** — не содержит логики, просто вызывает блоки
3. **HardwareInput изолирует GVL (вход)** — только этот блок читает датчики
4. **HardwareOutput изолирует GVL (выход)** — только этот блок пишет на двигатель
5. **Logic — чистая логика** — только технологическая логика и алгоритмы
6. **HMIInterface изолирует панель** — только этот блок обращается к кнопкам и лампам
7. **Легко портируется на другой ПЛК** — нужно изменить только HardwareInput, HardwareOutput и HMIInterface

## Глобальные переменные (GVL.st)

| Имя | Направление | Назначение |
|-----|-------------|------------|
| `DI_SensorA` | Вход | Оптический НЗ датчик в начале ленты |
| `DI_SensorB` | Вход | Оптический НЗ датчик в конце ленты |
| `DO_ComMotor` | Выход | Команда на двигатель конвейера |
| `DO_LampRun` | Выход | Лампочка на панели: лента работает |

## Соглашения

- Именование по конвенции: постфиксы `_PRG` для программ; префиксы `DI_`, `DO_` для сигналов железа; глобальные — через `GVL.*`.
- Порядок секций FB: `VAR_INPUT` → `VAR_OUTPUT` → `VAR`.
- Код пишется сразу после объявления переменных (без `BEGIN`/`END_FUNCTION_BLOCK`).
- Таймеры и прочие FB вызываются каждый цикл сканера.
- Логика работает только с символическими именами, прямая адресация (`%IX0.0`) допустима только в GVL.

## Работа с проектом

### CoDeSys v3 (Овен ПЛК210)

1. Создай новый проект под целевое устройство.
2. Импортируй объекты в дереве проекта:
   - `GVL.st` → Global Variable List `GVL`
   - `ConveyorMain.st` → Function Block `ConveyorMain`
   - `HardwareInput.st` → Function Block `HardwareInput`
   - `HardwareOutput.st` → Function Block `HardwareOutput`
   - `LogicDevice.st` → Function Block `LogicDevice`
   - `HMIInterface.st` → Function Block `HMIInterface`
   - `PLC_PRG.st` → Program `PLC_PRG` (назначить на MainTask, период 10 мс)
3. **Build → Generate Code** (F11).

### Онлайн-отладка

- **Force Write** (F7) — принудительно задать значение датчика для проверки логики.
- **Write** (Ctrl+F7) — однократная запись значения.
- Мониторинг: Watch `GVL` и локальные переменные `ConveyorMain`.

## Примечание о симуляции

Переменные в `GVL` объявлены без привязки к физическим адресам (`AT %I`/`%Q`). Для работы с реальным ПЛК добавь адресацию в `GVL.st` согласно карте вводов/выводов целевого контроллера.
