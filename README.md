# AutomationLab

Лаборатория опытно-экспериментальных технологических приложений.

Учебный проект управления конвейером на ПЛК: программа на языке **ST (Structured Text)** по стандарту **МЭК 61131-3**, среда разработки — **CoDeSys v3**. Целевой контроллер — **Овен ПЛК210**.

## Архитектура

Проект построен по принципу разделения ответственности: данные, алгоритм, аппаратура и интерфейс вынесены в отдельные блоки.

```
AutomationLab/
├── PLC_PRG.st                            ← Главная циклично вызываемая программа
├── GVL.st                                ← Глобальные переменные (входы/выходы)
└── TechnologyObject/                       ← Технологический объект "Конвейер"
    ├── ObjectType.st                   ← Тип данных объекта (STRUCT)
    ├── Main.st                           ← Блок-агрегатор объекта: вызывает все блоки
    ├── Model/
    │   └── Device.st                   ← Чистая технологическая логика
    └── Support/
        └── Hardware.st      ← Сопряжение с аппаратурой
```

### Поток данных за один цикл сканера

```
GVL.DI_SensorA (вход)
        │
        ▼
Hardware ──► Data.BoxOnEndPosition
        │
        ▼
Conveyer ──► Data.ComRotateLent (логика: NOT BoxOnEndPosition)
        │
        └──► Hardware ──► GVL.DO_ComMotor (двигатель)
```

### Назначение блоков

| Блок | Ответственность |
| ------ | ----------------- |
| `PLC_PRG` | Точка входа, циклический вызов объекта конвейера |
| `Main` | Владеет данными (`ConveyerType`), вызывает модель, железо и HMI |
| `Conveyer` | Алгоритм: команда на вращение ленты в зависимости от положения коробки |
| `Hardware` | Вход выход: чтение датчика и запись на двигатель |

### Глобальные переменные (GVL.st)

| Имя | Направление | Назначение |
| ----- | ------------- | ------------ |
| `DI_SensorA` | Вход | Оптический НЗ датчик на конце ленты |
| `DO_ComMotor` | Выход | Команда на двигатель конвейера |

## Соглашения

- Именование по конвенции: постфиксы `_PRG`, `_FB`; префикс `DT_` для типов данных; префиксы `DI_`, `DO_` для сигналов железа; глобальные — через `GVL.*`.
- Порядок секций FB: `VAR_INPUT` → `VAR_OUTPUT` → `VAR` → `VAR_IN_OUT`.
- Код пишется сразу после объявления переменных (без `BEGIN`/`END_FUNCTION_BLOCK`).
- Таймеры и прочие FB вызываются каждый цикл сканера.
- Логика работает только с символическими именами, прямая адресация (`%IX0.0`) допустима только в GVL.

## Работа с проектом в CoDeSys v3

### Сборка

1. Открой CoDeSys v3 и создай новый проект под целевое устройство (Овен ПЛК210) или используй профиль для симуляции.
2. Импортируй/создай объекты в дереве проекта согласно структуре выше:
   - `GVL.st` → Global Variable List `GVL`;
   - `ConveyerType.st` → DUT (Data Unit Type) `ConveyerType`;
   - `*.st` → Function Blocks с соответствующими именами;
   - `PLC_PRG.st` → Program `PLC_PRG`, назначенный на циклическую задачу (MainTask, рекомендуется период 10 мс).
3. Выполни **Build → Generate Code** (F11) — компиляция должна пройти без ошибок.

### Загрузка и отладка

1. Подключись к контроллеру: **Communication → Scan Network** (реальный ПЛК210) или выбери симулятор **Local Simulation**.
2. Загрузи проект: **Debug → Download** (Ctrl+F8).
3. Запусти: **Debug → Start** (F5).

### Онлайн-отладка

- **Force Write** (F7) — принудительно задать значение `DI_SensorA` для проверки логики без физического датчика.
- **Write** (Ctrl+F7) — однократная запись значения в переменную.
- Мониторинг: добавь `GVL` и `data` (внутри `Main`) в таблицу наблюдения Watch.

### Примечание о симуляции

Переменные в глобальном `GVL` объявлены без привязки к физическим адресам (`AT %I`/`%Q`). Для работы с реальным ПЛК добавь адресацию в `GVL.st` согласно карте вводов/выводов ПЛК210.
